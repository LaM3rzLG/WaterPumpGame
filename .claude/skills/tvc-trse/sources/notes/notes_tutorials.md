# TVC / TRSE Tutorial Catalog

Source directories surveyed:
- `/home/dey/trse/tutorials/TVC/tutorials/` — general TRSE-authored TVC tutorials (Crtc-unit graphics, effects, music)
- `/home/dey/trse/tutorials/TVC/tutorials_bertok/` — "Bery" (Zsolt Bertók) tutorials using the `TVC` ROM-routines unit and the `GE` (Game Engine) unit
- `/home/dey/trse/project_templates/tvc_image/` — minimal starter project skeleton

All examples target `system = TVC` and are TRSE Pascal-like `.ras` programs. TRSE `.trse` project files are IDE/compiler-settings files (zeropage allocations, optimizer passes, output type, etc.) — in this TRSE version they do **not** enumerate the project's `.ras` files in a `build_list`/file-list field; the only file-list-like fields seen are `open_files`/`current_file` (which files are open in the IDE) and `main_ras_file`, both mostly empty/`none` in these particular files. So "project file" here mainly captures compiler/zeropage configuration to reuse, not a manifest of modules.

### Examples table

| File | Technique demonstrated | Units used (`@use`) | Complexity / length |
|---|---|---|---|
| `tutorial_image.ras` | Displays a compressed 256×240 4-color TRSE image. Exports `.flf` source art to a compressed `.bin` at compile time via `@export`, includes it with `incbin(...) compressed`, sets `Crtc::mode_4_color`, sets a 4-entry palette, decompresses straight into VRAM at `$8000`. | `crtc`, `memory`, `system`, `text`, `compression` | Trivial — 34 lines, single static image, no loop logic beyond `loop()`. |
| `tutorial_image2.ras` | Same pattern but for 128×240 **16-color** mode (`Crtc::mode_16_color`), no explicit palette override (uses defaults). | `crtc`, `memory`, `system`, `text`, `compression` | Trivial — 29 lines. |
| `tutorial_image3.ras` | Same pattern but for 512×240 **2-color** (monochrome) mode (`Crtc::mode_2_color`), sets palette index 1 to green. | `crtc`, `memory`, `system`, `text`, `compression` | Trivial — 30 lines. |
| `twister.ras` | Classic demo-scene "twister" raster effect: precomputed sine table (`BuildTable`), lookup tables for character/frame offsets, scrolltext driven through a twisting sine-distorted tunnel, rendered via `memcpy` row copies into VRAM at `$8000`. Requires companion data generated by a "fjong" tool (`@requirefile` directive points at `data/twister_data.bin`, produced by `resources/fjong/twister.fjo`). 4-color mode with custom palette. | `crtc` only | Moderate — 80 lines; uses `offpage` loop optimization, pointer arithmetic, external data-generation step. |
| `plasma.ras` | Classic plasma effect: two small sine-shift tables (`siny`/`sinx`) placed at fixed zero-page-like addresses (`at $7F00`/`$7E00`), a base 256-entry sine table via `buildsinetable`, and a "smooth" color-ramp data blob generated externally (`resources/fjong/generate_data.fjo` → `data/smooth_data.bin`). Inner pixel loop is **hand-written inline 6502-style assembly** (`asm("...")`) with a `repeat`/`repend` unrolled loop for speed. 4-color mode, custom palette. | `crtc` only | Moderate/advanced — 111 lines; mixes Pascal control flow with inline assembly for performance-critical inner loop; good reference for the "how to drop into asm" pattern. |
| `music.ras` | Same plasma effect as `plasma.ras`, extended to demonstrate the **Music unit**: non-blocking interrupt-driven SID-derived music playback. Shows two playback configurations — `Music::INTERRUPT_FREQ_5008` non-looped track and `Music::INTERRUPT_FREQ_8491` looped track — via `Music::Init`, `Music::Play`, `Music::IsMusicFinished`, `Music::Stop`. Extensive header comments document the full asset pipeline: convert a `.sid` tune to TVC format using `SIDDumpTVCGUI` (Windows tool), then `incbin` the resulting `.bin`. Links to TVC.hu resources, GoatTracker, HVSC/deepsid archives for source SID music. | `Music`, `crtc` | Moderate — 141 lines; best available reference for audio/music integration and the SID→TVC asset pipeline. |

Supporting assets in `tutorials/`:
- `data/` — pre-generated binary blobs consumed by the above: `music_test1_sid.bin` (3.5KB), `music_test2_sid.bin` (4.5KB), `smooth_data.bin` (256B), `twister_data.bin` (6KB), `twister_table.bin` (13KB).
- `resources/fjong/` — `.fjo` scripts (`generate_data.fjo`, `twister.fjo`) that are run through TRSE's "fjong" data-generation tool to produce the `data/*.bin` files consumed by `plasma.ras`/`music.ras` and `twister.ras` respectively. Useful to note as a build-pipeline dependency (these tutorials are not fully self-contained from source assets alone — the generation step must be re-run or the .bin outputs reused as-is).
- `resources/images/` — `.flf` TRSE native image-format sources: `image1.flf` (31KB, used by `tutorial_image2.ras` and `twister.ras`), `image2.flf` (123KB, used by `tutorial_image3.ras`), `trse.flf` (61KB, used by `tutorial_image.ras`).

### `files/main.ras` (full contents, verbatim)

```pascal
program ShowCompressedImage;
@use "crtc"
@use "memory"
@use "system"
@use "text"
@use "compression"
 
 
// Automatically export 256x240 16-color image

@export "resources/images/image.flf" "resources/images/image.bin" 256

var  
// Include the exported image data + palette
	image : incbin("resources/images/image.bin") compressed;
	
	
begin
	Crtc::SetMode(Crtc::mode_16_color);
	Crtc::EnableVRAM();
	// Decompress to VRAM
	Compression::Decompress(#image, $8000);

	loop();	

end.
```

This is essentially identical in structure to `tutorials/tutorial_image2.ras` (same 16-color compressed-image pattern) — confirms that `tutorial_image2.ras` is effectively the "reference implementation" this project template was derived from, and is the best minimal skeleton to hand to the skill for "start a new TVC TRSE project" scaffolding: standard `uses` list (`crtc`, `memory`, `system`, `text`, `compression`), `@export` directive to auto-convert a `.flf` art asset into a compiled `.bin` blob at build time, `incbin(...) compressed` to embed it, and the three-call runtime pattern `Crtc::SetMode` → `Crtc::EnableVRAM` → `Compression::Decompress(#image, $8000)` → `loop()`.

## Summary observations for skill-building

- **Two distinct API layers are demonstrated across the corpus**: the low-level `Crtc`/`TVC`/`Music`/`compression`/`memory`/`text`/`system` units (used throughout `tutorials/` and in `tutorial_tvc.ras`) versus the higher-level `GE` (Game Engine) unit used only in `tutorials_bertok/SpriteDemo.ras` and `SpaceWar.ras`. A skill should probably document both layers: `Crtc`/`TVC` for direct hardware/ROM access (graphics modes, palettes, raster sync, sound), and `GE` for sprite/image/animation abstractions built on top.
- **`SpaceWar.ras` (893 lines) is the single richest reference** for a complete game architecture (state machines, entity records, collision detection, sound+graphics interleaving, level/game-over flow) and is confirmed to compile (ships with `.bin`/`.cas`).
- **`music.ras`** is the only example covering the SID-derived music pipeline end-to-end (with external tool links in comments) — valuable to preserve verbatim as a reference for audio integration.
- **`plasma.ras`** is the best example of embedding raw inline assembly (`asm("...")` with `repeat`/`repend` unrolling) inside TRSE Pascal for performance-critical code — useful for a skill section on "when/how to drop to assembly."
- **Asset pipeline dependencies**: `twister.ras`, `plasma.ras`, and `music.ras` all depend on externally generated binary data (`.fjo` fjong scripts, or externally-converted `.sid`→`.bin` audio) that isn't produced by TRSE itself at compile time — the `.bin` outputs are checked in already, but a skill instructing someone to build *new* content in these styles needs to explain those companion toolchains, not just the `.ras` source.
- **Project file format caveat**: none of the three `.trse` files examined populate `build_list` (it's always empty, `,`) — so a `.trse` project file is not a manifest of source files to compile; each `.ras` program is compiled individually. The project file instead centralizes zeropage allocation, optimizer flags, and system/output-format settings shared across a workspace, plus (in the template) which file is currently open in the IDE (`open_files`/`current_file`).
